# 관리자 검토 기능 통합

## 기준과 범위

- 기준: itproanalysis/donghaeng_finance_ai, feature/service-review-completion, 7277f35f8ceeb1adb91ad1c409fd442ce22e339c.
- 참조: `ModelingReviewDraft`의 검토 상태, `ModelingInstitutionReport`의 현황·원문·계획·누락·의견 구성, `InstitutionConsultation`의 최신 저장 기록 내보내기와 미저장 의견 보호.
- 해당 브랜치의 GCP/Node 서버 전체를 병합하지 않고, 기존 Sites/D1 인터뷰 계약에 맞게 검토 흐름을 이식했다. 최신 브랜치의 다섯 작업 단계 중 검토 요약, 답변과 근거, 계획과 실행, 담당자 검토, 자료 내보내기를 현재 관리자 화면에 반영했다.
- 현재 연결 대상은 느티나무감자탕 시나리오의 직접 입력 답변 12개와 `feature_schema_v2` 100개 변수 사전이다. 답변과 사업 프로필에서 확인할 수 있는 변수만 서버에서 산출하고, 거래·신용·외부 자료가 필요한 변수는 사유가 있는 `MISSING/null`로 남긴다. 합성 사례의 94개 모델링 Vector와 혼합하지 않는다.
- 회복 계획 선택, append-only 실행 기록, 기관 선택, 준비 자료·담당자·점검 기간을 D1에 저장한다. 기관 선택은 공식 상담 경로를 정리하기 위한 것이며 자동 전송·승인 판단은 포함하지 않는다.
- 기존 사이트 접근 정책을 유지한다. 새로운 다중 사용자 역할 체계를 추가한 작업이 아니다.

## 시각 방향

- Visual thesis: 랜딩의 고운바탕체, 저녁 골목의 차콜, 따뜻한 종이색으로 차분한 상담 기록실을 구성한다.
- Content plan: 상담 선택 → 현황·미응답 확인 → 원문 근거 → 계획·실행 확인 → 검토 의견 → 검토서 내보내기. 관리자 업무 앞에 히어로를 추가하지 않는다.
- Interaction thesis: 기존 상단 이동 표시 유지, 내용 전환 시 짧은 등장, 답변 펼침과 탭 밑줄로 상태를 표현. reduced-motion에서는 제거한다.

## 데이터와 보호 장치

- 기존 답변·메모·체크리스트를 보존하는 추가 컬럼 migration만 사용한다.
- `GET /api/interview/report`: 한 번 읽은 저장 기록을 바탕으로 원문, Canonical 연결, 100개 변수의 산출·누락 상태, 회복·기관 준비, 저장된 검토 의견을 반환한다. 금액·비율·기간은 명시된 단위만 보수적으로 구조화하며 신용점수를 생성하지 않는다.
- 완료 답변에는 답변 순서와 revision으로 만든 안정적인 분석 지문을 표시한다. 같은 저장본은 조회 시각과 무관하게 같은 지문을 유지한다.
- `PUT /api/interview`: 답변·검토·상담 준비 버전의 조건부 갱신으로 동시 편집 덮어쓰기를 차단한다. 실행 기록은 기존 배열을 읽은 뒤 새 기록만 추가하며 기존 기록을 UI에서 수정·삭제하지 않는다.
- `SELF_REPORTED`와 `MISSING`을 구분하며 진술을 증빙 검증 완료로 표시하지 않는다.
- 미저장 의견이 있으면 JSON/인쇄를 비활성화한다. 내보내기 직전 최신 서버 기록을 읽으며, 인쇄 전용 레이아웃을 사용한다.
- 부분 응답도 진행 중 자료로 내보낼 수 있다. 누락과 미확인 점검 항목을 그대로 포함한다. 기관 전송은 수행하지 않는다.
- 브라우저 인쇄의 PDF 저장 기능을 이용한다. 별도 PDF 생성 서버는 없다.
- 탭은 좌우 방향키, Home, End로 이동할 수 있고 현재 패널과 접근성 관계를 유지한다. `/demo/admin`, `/modeling`, `/consultation/:id` 호환 경로도 같은 저장 기록을 연다.

## 검증

빌드 후 `node --test tests/*.test.mjs`를 실행한다. 실제 SQLite에 모든 migration을 적용한 Worker 테스트로 원문 보존, 100개 사전·누락 정책, 안정 지문, 검토·상담 준비 버전 충돌, append-only 실행 기록, 보고서 읽기의 비변경성을 확인한다.
